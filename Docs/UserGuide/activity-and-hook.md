# 实时任务与 CodexBar Hook

简体中文 | [English](../en/UserGuide/activity-and-hook.md)

CodexBar Hook 用于显示实时任务，并支持任务通知、触觉反馈、按任务防睡眠，以及每日会话、轮次和工具调用统计。开启后也可以同步或重建这些每日统计。

## 开启方法

1. 打开 `设置 > 高级`
2. 开启 `CodexBar Hook` 并等待校验完成
3. 开始一轮 Codex 任务，在主面板查看状态

Hook 要求当前使用的 Codex 为 `0.150.0` 或更高版本。更新后仍提示版本过低时，在 `设置 > 关于` 点击 `重新建立连接`。其他错误见 [常见问题与排查](troubleshooting.md#hook-无法开启或校验失败)

CodexBar 自动检查和修复已开启的 Hook 配置，保留用户和其他 App 的 handler。确认 Codex 低于最低版本时，会关闭 Hook 并移除自己的 handler；更新 Codex 后需要重新开启 Hook。暂时无法连接或确认版本时保留配置，等待下次校验。

## 任务状态

| 状态 | 含义 |
| --- | --- |
| 运行中 | Codex 正在处理任务 |
| 等待批准 | 需要你批准下一步操作 |
| 最近完成 | 一轮任务已结束，不代表结果一定成功 |
| 最近终止 | 中断或其他终态信号确认任务终止，不发送完成通知 |

收到 `Stop` 后会先显示“正在收尾”；仍有子 Agent 等待批准时优先显示等待。确认本轮完成且满足通知设置后才发送完成提醒，期间中断则显示已终止。

中断只结束对应轮次，同一会话随后开始的新任务保持活跃。全部符合条件的任务结束后，按任务防睡眠会释放。

子 Agent 的活动合并到所属任务中。内部自动审核任务和来源始终无法确认的任务不显示为实时任务，也不触发流光、任务提醒或防睡眠；它们的活动仍计入每日统计。同一会话和轮次已确认是正常任务后，后续暂时无法识别来源的事件仍会更新任务状态。

主 Agent 或子 Agent 等待批准时，其他 Agent 的进展不会解除它的等待。只要该任务仍有一项用户审批等待，卡片就继续显示等待状态。

来源明确但无法识别会话的任务会带有橙色匿名图标。这类任务可以查看，但不触发通知或触觉反馈，也不参与防睡眠和异常会话保护。

长时间没有进展的运行任务可能被 [异常会话保护](sleep-prevention.md#异常会话保护) 隐藏，恢复进展后重新显示。

## 每日统计

在主面板热力图上悬停日期，可查看当天的会话数、对话轮次、工具调用、权限请求、上下文压缩、子 Agent 和最常用模型。

会话和轮次按天去重，跨天继续活动会计入新的一天。当天只有会话结束事件的会话，以及只有完成候选或中断事件的轮次，不计入当天活跃数。工具调用按开始和结束事件数的较大值统计。

## 关闭 Hook

关闭后，实时任务、任务通知、触觉反馈、防睡眠、Hook 统计及其跨设备同步停止更新。账户、额度和 Token 热力图仍可使用。

Hook 记录任务的时间、模型、工具名和项目等信息，不保存提问、回复或工具输入输出正文。保存期限与同步内容见 [数据、同步与隐私](sync-data-privacy.md)
