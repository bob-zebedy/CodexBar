## 1. 快速开始

### 使用要求

- macOS 15.0 或更高版本
- 已安装 Codex CLI 或 Codex App
- 已在 Codex 中完成登录

CodexBar 是纯菜单栏 App，不显示 Dock 图标，也没有传统主窗口。启动后请在屏幕顶部菜单栏寻找带对勾的人物图标。

### 第一次使用

1. 左键点击菜单栏图标，确认账号、额度和 Token 用量能够显示。
2. 右键点击菜单栏图标，选择「设置」。
3. 根据需要开启「开机自动启动」和「自动检查更新」。
4. 如果希望在菜单栏直接看到剩余额度，开启「菜单栏额度指示」并选择额度窗口。
5. 如果希望查看工作流统计、实时任务或任务提醒，开启「CodexBar Hook」。
6. 开启 Hook 后，可继续开启「主面板任务中心」「阻止系统休眠」和「跨设备同步」。
7. 如果希望接收提醒，开启「系统通知」，允许 macOS 通知权限，再打开右侧的通知选项。

如果第一步显示「未登录」或「初始化失败」，先阅读[账号状态与数据刷新](#4-账号状态与数据刷新)。

## 3. 看懂菜单栏图标

菜单栏图标同时表达账号、额度和实时任务三类信息。将鼠标停在图标上，可以查看文字摘要。

### 人物图标

| 图标         | 含义                               | 建议操作                                   |
| ------------ | ---------------------------------- | ------------------------------------------ |
| 带对勾的人物 | Codex 账号数据可用                 | 正常使用                                   |
| 带叉的人物   | 未登录、初始化失败或当前数据不可用 | 打开菜单查看具体状态，再按账号排障步骤处理 |

### 左侧额度竖条

开启「菜单栏额度指示」后，人物图标左侧会显示所选额度窗口的剩余比例。设置行右侧的下拉菜单可以切换额度窗口。

| 剩余额度   | 颜色 | 含义       |
| ---------- | ---- | ---------- |
| 80% 及以上 | 绿色 | 额度充足   |
| 60%–79%    | 蓝色 | 额度较充足 |
| 40%–59%    | 黄色 | 建议留意   |
| 20%–39%    | 橙色 | 额度较低   |
| 低于 20%   | 红色 | 额度紧张   |

如果开关已经开启但没有竖条，通常是所选额度窗口暂时没有可用数据。打开设置切换到另一个窗口，或双击账号卡片人物图标刷新。

### 右下角任务状态点

任务状态点需要开启 Codex Hook。

| 状态点   | 含义                             |
| -------- | -------------------------------- |
| 橙色     | 至少有一个任务正在等待用户批准   |
| 蓝色     | 至少有一个任务正在运行           |
| 绿色     | 有任务刚刚完成，通常保留约 30 秒 |
| 无状态点 | 当前空闲，或任务数据暂不可用     |

多个状态同时出现时，优先显示：等待批准 → 运行中 → 刚完成 → 空闲。

如果活动卡片显示「暂无数据」，状态点也不会显示。此时先处理账号或主数据加载问题。

## 4. 账号状态与数据刷新

### 需要什么

账号卡片不需要额外开关，但需要本机已安装并登录 Codex CLI 或 Codex App。

### 账号卡片显示什么

- 当前账号邮箱或账号名称
- 当前订阅类型
- 数据刷新状态

双击邮箱可以临时模糊显示，适合共享屏幕或截图；再次双击即可恢复。账号发生变化后，模糊状态会自动恢复为正常显示。

### 刷新数据

CodexBar 默认每 60 秒刷新一次账号、额度和 Token 用量。菜单底部「数据更新时间」左侧的蓝色圆环表示距离下一次自动刷新还有多久。

需要立即刷新时，双击账号卡片左侧的人物图标。刷新期间人物图标旁会出现小型进度指示，完成后倒计时重新开始。

### 状态与处理方法

| 状态                   | 含义                                     | 处理方法                                                         |
| ---------------------- | ---------------------------------------- | ---------------------------------------------------------------- |
| 「未登录」橙色提示     | CodexBar 没有读取到已登录账号            | 在 Codex CLI 或 Codex App 中完成登录，再双击人物图标刷新         |
| 「初始化失败」红色提示 | 没有成功启动或连接本机 Codex             | 检查 Codex 是否仍安装，打开设置确认 Codex 版本与路径，再查看日志 |
| 「暂无数据」           | 账号已识别，但当前没有可展示的额度或用量 | 等待自动刷新，或手动刷新；持续出现时查看日志                     |
| 额度或热力图变淡       | 本轮刷新失败，当前显示的是较早缓存       | 网络或本机 Codex 恢复后再次刷新                                  |
| 长时间显示刷新中       | 本次读取可能超时或连接异常               | 等待状态结束后重试，并在日志中查看最新错误                       |

如果安装了多个 Codex，设置中的「Codex 版本」会标记「当前使用」的来源。确认它是否是你实际登录和使用的版本。

## 5. 额度、重置时间与手动重置机会

### 需要什么

主面板额度不需要额外开关，只需要账号已登录并返回额度数据。「菜单栏额度指示」只控制菜单栏竖条，不会隐藏主面板额度。

### 查看额度

每个额度窗口会显示：

- 窗口名称
- 分段额度条
- 剩余百分比
- 下一次重置时间

额度条和百分比使用与菜单栏竖条相同的绿色、蓝色、黄色、橙色和红色分档。某个窗口显示 `--`，表示当前没有该项数据或重置时间。

### 在菜单栏持续显示额度

1. 打开设置。
2. 开启「菜单栏额度指示」。
3. 在右侧下拉菜单选择希望关注的额度窗口。

关闭后，CodexBar 会记住最后选择的窗口，下次开启时自动恢复。

### 查看手动重置机会

如果账号存在可用的手动重置机会，主额度标题右侧会显示绿色的 `重置次数: N`。

点击后，侧边面板会按过期时间从近到远列出每批机会：

| 数量颜色 | 含义               |
| -------- | ------------------ |
| 绿色     | 距离过期超过 7 天  |
| 橙色     | 将在 7 天内过期    |
| 红色     | 将在 24 小时内过期 |

`重置次数: N` 用于查看机会和过期时间，不会直接执行额度重置。

### 常见问题

#### 为什么看不到 `重置次数: N`？

只有账号当前存在大于零的可用机会时才显示。手动刷新后仍没有，表示当前没有可展示的机会。

#### 为什么显示「未知过期时间」？

CodexBar 已读取到可用次数，但暂时没有取得有效过期时间。次数仍会显示，可以稍后再次刷新。

#### 为什么额度突然变淡？

当前显示的是较早缓存，不一定是最新结果。双击人物图标刷新；如果持续变淡，请查看日志中的额度读取错误。

#### 为什么菜单栏竖条和主面板不一致？

先确认设置中选择的是哪个额度窗口。主面板可能同时展示多个窗口，而菜单栏只显示选中的一个。

## 6. Token 摘要与近 30 周热力图

### 需要什么

- Token 摘要和热力图不需要额外开关。
- 热力图中的工作流明细需要开启「CodexBar Hook」。

### 摘要指标

用量区域会根据可用数据展示：

| 指标           | 含义                              |
| -------------- | --------------------------------- |
| 全时累计 Token | 当前可读取范围内的累计 Token 用量 |
| 单日峰值       | 单日 Token 用量最高值             |
| 当前连胜       | 最近连续有使用记录的天数          |
| 最长连胜       | 历史最长连续使用天数              |
| 最长任务       | 可识别到的最长任务耗时            |

### 使用热力图

热力图以周为列、日为行展示近 30 周。蓝色越深，表示当天 Token 用量相对于当前 30 周峰值越高。

把鼠标移到任意日期方块上，侧边详情会自动出现。详情跟随鼠标悬停，不需要点击；如果消失，将鼠标重新移回日期即可。

### Hook 开启后的每日统计

| 指标       | 含义                                  |
| ---------- | ------------------------------------- |
| 用量强度   | 当天 Token 相对于当前热力图峰值的强度 |
| 最热模型   | 当天出现次数最多的模型                |
| 会话总数   | 当天识别到的 Codex 会话数量           |
| 对话轮次   | 当天识别到的任务轮次数量              |
| 子智能体   | 当天记录到的子 Agent 活动数量         |
| 调用工具   | 当天记录到的工具调用数量              |
| 权限请求   | 当天请求用户批准操作的次数            |
| 上下文压缩 | 当天发生的上下文压缩次数              |

### 常见问题

#### 为什么某天有 Token，却没有工作流明细？

Token 用量和 Hook 工作流统计来自不同功能。请确认当天使用 Codex 时 Hook 已开启，并检查设置中的 Hook 是否有错误提示。

#### 为什么今天显示 `--`？

今天的工作流活动可能已经出现，但 Token 用量尚未更新。等待下一次自动刷新即可。

#### 为什么工作流次数和 Token 数对不上？

工作流次数表示会话、轮次和事件数量，Token 表示用量，两者不是相同口径，不需要逐项对应。

#### 为什么悬停后看不到侧边详情？

将鼠标准确移动到有颜色的日期格上。如果菜单靠近屏幕边缘，详情会自动改到另一侧显示。

## 7. Codex Hook、活动卡片与任务中心

### Hook 提供什么

开启 Codex Hook 后，CodexBar 可以：

- 在热力图中显示每日工作流统计
- 在活动卡片中显示当前任务
- 在任务中心查看并发任务
- 在菜单栏人物图标上显示实时状态点
- 发送任务等待和任务完成通知
- 提供任务触觉反馈
- 使用跨设备同步合并每日工作流统计

### 开启步骤

1. 打开设置。
2. 开启「CodexBar Hook」。
3. 等待开关更新完成，确认下方没有错误提示。
4. 开启「主面板任务中心」，让活动卡片显示在主面板中。

「主面板任务中心」依赖 Hook。Hook 关闭时，该开关会显示为关闭并置灰；重新开启 Hook 后会恢复此前选择。

### 防止任务因系统休眠中断

长时间运行 Codex 任务时，即使任务本身没有结束，macOS 也可能因为长时间无人操作或 MacBook 合盖而进入休眠。开启「阻止系统休眠」后，CodexBar 会根据 Hook 提供的实时任务状态，只在确实还有任务运行时暂时阻止系统休眠；没有其他任务运行时，任务等待你处理、已经结束或超过保护时限后，会把休眠控制权交还给 macOS。

这个功能适合编译、分析、批量修改等需要离开电脑继续运行的长任务。它不是一个让 Mac 永久保持唤醒的总开关，也不会改变每个任务本身的执行逻辑。

#### 它能阻止什么

功能生效时，CodexBar 会同时处理几种常见的系统休眠来源：

| 使用场景                           | CodexBar 的行为                                            |
| ---------------------------------- | ---------------------------------------------------------- |
| Mac 开盖，但长时间没有键盘鼠标操作 | 阻止系统因空闲而休眠                                       |
| MacBook 合盖                       | 阻止普通合盖休眠，让正在运行的任务继续                     |
| 从 Apple 菜单等位置手动请求休眠    | 正在保护任务时阻止这次系统休眠                             |
| 屏幕自动熄灭或系统锁屏             | 不阻止；屏幕熄灭和系统休眠是两件事，屏幕关闭时任务仍可继续 |
| 关机、重启、断电或电量耗尽         | 无法阻止                                                   |
| 网络中断、Codex 报错或任务自身终止 | 无法阻止；这个功能只控制系统休眠，不保证任务一定成功       |

如果你希望立即让 Mac 休眠，请先停止正在运行的任务，或直接关闭「阻止系统休眠」后再操作。开关仍然开启时，可以用设置行是否显示「当前允许系统休眠」确认任务已经不再受到保护。

#### 开启与授权

1. 打开设置并先开启「CodexBar Hook」。
2. 开启「阻止系统休眠」，再从右侧菜单选择「最长阻止时间」。
3. 首次开启时，如果设置行显示「需要授权允许 CodexBar 后台运行」，点击「打开系统设置」。
4. 在 macOS「系统设置」→「通用」→「登录项与扩展」的 App 后台活动列表中允许 CodexBar，然后回到 CodexBar。设置行会在 App 再次激活时自动刷新。
5. 启动一个 Codex 任务；设置行显示「当前禁止系统休眠」时，说明功能已经生效。没有任务运行时显示「当前允许系统休眠」是正常状态。

这项功能必须依赖 Hook，因为 CodexBar 需要靠 Hook 分辨任务是在运行、等待批准还是已经结束。关闭 Hook 时，防休眠开关会自动关闭并置灰，系统休眠设置也会恢复；之后重新开启 Hook，不会自动重新开启防休眠，需要由你再次确认。

「App 后台活动」授权和设置中的「开机自动启动」是两件事。前者允许随 App 安装的后台辅助服务切换和恢复系统休眠设置，后者决定登录后是否自动打开 CodexBar 主应用。

#### 什么时候会真正阻止休眠

设置开关保持开启只表示“允许 CodexBar 在需要时保护任务”，不表示系统此刻一定不能休眠。CodexBar 使用与活动卡片和任务中心相同的实时状态来决定是否生效：

| 当前任务情况                         | 是否阻止系统休眠 | 原因                             |
| ------------------------------------ | ---------------- | -------------------------------- |
| 至少有一个任务正在运行               | 是               | 仍有实际工作需要继续             |
| 一部分任务等待批准，另一部分仍在运行 | 是               | 只要还有一个任务运行，就继续保护 |
| 所有任务都在等待用户批准             | 否               | Codex 已经暂停工作，等待你的操作 |
| 任务全部完成、终止或不再活动         | 否               | 没有需要继续保护的任务           |
| 已达到最长阻止时间                   | 否               | 防止异常任务让电脑无限期保持唤醒 |
| Hook 关闭或防休眠开关关闭            | 否               | CodexBar 不再接管系统休眠        |

“等待用户批准”只指 Codex 已经确认需要你亲自处理的请求。某些权限请求会由自动审核流程继续处理，这时任务仍算运行中，CodexBar 也会继续阻止休眠。

一个常见过程是：任务运行时阻止休眠；任务停下来等待你批准时恢复系统休眠；你批准后任务重新开始运行，CodexBar 再次阻止休眠。这样可以保护真正执行中的工作，又不会在任务整晚等待输入时持续耗电。

#### 最长阻止时间

可选时限为 1、2、4、8、12、24 小时或无限制，默认是 12 小时。这个时限不是任务超时时间：到期只会允许系统重新休眠，不会取消、终止或修改 Codex 任务。

多个任务共享同一个防休眠周期，而不是每个任务各自倒计时。周期按下面的方式计算：

- 第一个运行任务出现时开始计时。
- 后来又启动一个新任务时，从新任务启动的时刻重新获得完整时限。
- 等待批准的任务获批并恢复运行时，也从恢复时刻重新获得完整时限。
- 同一任务只是继续输出内容、调用工具或产生普通 Hook 活动，不会延长时限。重新打开设置、激活 CodexBar 或刷新状态也不会延长。
- 所有运行和等待任务都消失后，当前周期结束；下次出现任务时重新计时。
- 关闭再开启防休眠后，如果此时仍有任务运行，会建立一个新的周期。

例如，最长时间设为 12 小时：任务 A 在 10:00 启动，原本会保护到 22:00；任务 B 在 15:00 新启动后，共享截止时间会改为次日 03:00。A 或 B 的普通进度更新不会继续顺延。如果任务在 16:00 等待你批准，并在 16:30 获批恢复运行，则会从 16:30 再获得完整的 12 小时。

达到上限后，即使原任务仍显示运行中，CodexBar 也会恢复系统休眠；该任务后续的普通活动不会自动重新开启保护。此后启动新任务，或让等待批准的任务恢复运行，才会开始新的完整周期。

运行中修改时限会按当前周期的起点重新计算。改成更短时，如果新时限已经过去，会立即恢复休眠；改成更长时，只要按新时限计算还没有到期，就会继续保护。改成「无限制」会取消本周期的自动到期限制，但仍会在任务等待、结束、功能关闭或 CodexBar 退出时恢复系统休眠。无限制可能显著增加耗电，建议只在明确需要时使用。

#### 任务停止运行后会发生什么

开始保护任务前，CodexBar 会记住电脑原本的休眠设置；结束保护时恢复这个原始状态，而不是一律强制开启休眠。因此，如果你在任务开始前已经通过其他工具全局禁止休眠，CodexBar 结束后会保留那个选择。相反，也不建议在保护期间同时使用其他工具修改同一项全局休眠设置，因为结束时 CodexBar 会按任务开始前记录的状态恢复。休眠设置作用于整台 Mac，也应避免同时运行来自不同安装位置的多个 CodexBar。

恢复设置不等于无条件让电脑立刻睡眠。CodexBar 会先交还休眠控制权，再让 macOS 根据已经累计的空闲时间、最近是否有人操作、其他 App 是否也在阻止休眠以及当前电源策略重新判断：

- Mac 开盖时，如果早已达到系统设定的空闲时间，可能很快进入休眠；如果你刚操作过电脑，或其他 App 仍在保持唤醒，也可能继续运行。
- MacBook 普通合盖、没有处于外接显示器合盖工作模式，并且任务开始前的设置允许休眠时，CodexBar 会在恢复设置后请求系统进入休眠。
- MacBook 合盖连接外接显示器，并且 macOS 允许合盖工作时，只恢复原设置，不会强制休眠。

正常退出 CodexBar 时会主动恢复休眠设置。如果 App 意外退出或与后台服务失去连接，后台服务会根据此前保存的恢复记录进行兜底，通常在约 15 秒的宽限时间后恢复。这个短暂等待是为了避免 CodexBar 更新或快速重连时来回切换系统状态。

关闭防休眠后，CodexBar 的后台项目仍可能继续出现在「登录项与扩展」列表中，这不表示系统仍被禁止休眠。保留后台服务是为了下次启用以及在异常情况下完成恢复；是否正在阻止休眠，应以 CodexBar 设置行的当前状态为准。

#### 后台权限与隐私

之所以需要后台项目授权，是因为普通 App 只能可靠阻止空闲休眠，无法保证 MacBook 合盖后继续运行。CodexBar 使用随 App 一起签名的 CodexBarHelper 完成必要的系统级切换。

这个辅助服务的能力受到严格限制：它只响应同一签名的 CodexBar，只能在“阻止休眠”和“恢复原设置”之间切换，并在本机保存一条用于异常恢复的状态记录。它不能接收任意命令或文件路径，不访问网络，也不读取 Codex 账号、提示词、回复、任务内容、会话信息或 Hook 原始记录。你不需要在终端运行 `sudo` 或手动修改系统休眠设置。

#### 状态提示与排查

| 设置行提示                     | 表示什么                                 | 建议操作                                                          |
| ------------------------------ | ---------------------------------------- | ----------------------------------------------------------------- |
| 需要启用 CodexBar Hook         | CodexBar 无法取得可靠的实时任务状态      | 先开启 Hook；重新开启 Hook 后还要手动重新开启防休眠               |
| 需要授权允许 CodexBar 后台运行 | 后台服务已经注册，但仍在等待 macOS 授权  | 点击「打开系统设置」，在「登录项与扩展」中允许 CodexBar           |
| CodexBarHelper 尚未注册        | 后台服务还没有准备好                     | 短暂出现可等待刷新；持续显示时确认 App 位于「应用程序」并重新安装 |
| 当前允许系统休眠               | 功能已就绪，但当前没有需要保护的运行任务 | 通常无需处理；查看活动卡片确认任务是否正在运行                    |
| 当前禁止系统休眠               | 至少一个任务正在运行，保护已经生效       | 可以继续使用或合盖运行，同时注意散热和电量                        |
| 已达到禁用休眠上限             | 当前周期已经到期，系统休眠设置已恢复     | 需要继续时启动新任务、恢复等待任务，或重新评估最长阻止时间        |
| 红色错误信息                   | 注册、连接或切换休眠状态失败             | 打开日志查看最新错误；持续失败时退出并重新打开或重新安装 CodexBar |

如果设置显示「当前允许系统休眠」，但你认为任务仍在运行，先查看活动卡片和任务中心：任务可能已经进入等待批准，或者当前周期已经达到上限。如果活动卡片也无法正确显示状态，请先排查 Hook。

如果合盖后任务仍然停止，请依次确认：Hook 和防休眠开关都已开启；后台项目已经授权；合盖前设置行显示「当前禁止系统休眠」；当前周期尚未达到上限；任务不是在等待批准。还应检查任务是否因为断网、Codex 错误或其他与休眠无关的原因停止。

如果功能关闭后 Mac 没有立刻休眠，这通常不表示恢复失败。macOS 仍会考虑最近的用户操作、其他 App 的唤醒请求和系统电源策略。只有设置行出现红色错误，或长时间无法恢复正常状态时，才需要查看日志进一步处理。

#### 使用安全

合盖运行会持续耗电并产生热量，CodexBar 不会根据低电量自动结束防休眠。请确保 Mac 通风良好，接通合适的电源，不要把仍在运行任务的电脑放进背包、保护套或其他密闭空间。需要携带电脑前，请停止任务并确认设置行已经显示「当前允许系统休眠」，或直接关闭该功能后再合盖携带。

系统更新、关机、断电和电池耗尽仍会中断任务。对于无法轻易重跑的重要任务，建议同时保存中间结果，不要把防休眠功能当作任务可靠性的唯一保障。

### 使用任务中心

点击活动卡片即可打开任务中心。任务按以下分组展示：

- 等待确认
- 运行中
- 最近完成
- 最近终止

最近完成和最近终止通常保留约 10 分钟。任务中心优先显示在主面板右侧，空间不足时会自动切换到左侧；任务较多时可以在面板内滚动。

「完成」表示该轮任务已结束，不评价结果是否符合预期；「终止」表示没有收到正常完成状态，因此不会显示绿色菜单栏状态，也不会触发任务完成通知。

### 常见问题

#### 为什么 Hook 已开启，活动卡片仍显示「暂无 Codex 活动」？

这表示主数据正常，但当前没有运行、等待、最近完成或最近终止的任务。启动一个新的 Codex 任务后再观察。

#### 为什么活动卡片显示「暂无数据」？

主面板账号或用量数据还没有准备好。先解决「未登录」「初始化失败」或「暂无数据」，再检查任务状态。

#### 为什么有任务在运行，但 CodexBar 没有显示？

依次检查：

1. 「CodexBar Hook」是否开启且没有错误。
2. 「主面板任务中心」是否开启。
3. 该任务是否在开启 Hook 后启动。
4. 当前使用的 Codex 是否为设置中标记「当前使用」的版本。
5. 日志中是否有 Hook 验证或读取错误。

#### 为什么任务显示运行中但没有精确耗时？

CodexBar 没有取得可信的任务开始时间时，只显示「正在运行」，不会显示可能不准确的时长。

#### 为什么 Codex 已关闭，任务仍显示运行中？

强制关闭、崩溃、终端直接退出或电脑断电时，任务可能没有留下结束状态。后续新任务通常会使旧任务转为最近终止；如果一直没有新活动，旧状态最多可能保留约 24 小时。

#### 能否手动删除一条卡住的任务？

当前没有单任务删除按钮。等待后续任务更新状态，或等待旧活动自动过期。

#### 移动 CodexBar 后 Hook 不工作怎么办？

Hook 与当前 App 位置相关。建议先在旧位置关闭 Hook，把 App 移到最终位置，再重新开启。不要同时运行多个不同位置的 CodexBar，否则可能重复记录同一活动。

#### 关闭 Hook 会删除历史统计吗？

不会。关闭后会停止记录新活动，并隐藏活动卡片和 Hook 统计；重新开启后，仍可继续使用保留的历史数据。

## 8. 重建工作流统计

### 什么时候使用

当某段日期的工作流统计缺失、重复或与本机记录不一致时，可以使用设置中的「重建数据」。日常使用不需要定期重建。

### 需要什么

- 所选日期在本机仍有 Hook 原始记录。
- 当前可选择最近 210 天内的日期。
- 是否正在开启 Hook，不影响对已有本机记录执行重建。

### 操作步骤

1. 打开设置，找到「重建数据」。
2. 点击「选择日期范围」。
3. 第一次点击选择开始日期，第二次点击选择结束日期。
4. 只重建一天时，连续点击同一天两次。
5. 检查设置行下方显示的选择结果。
6. 点击「重建」，在确认窗口中再次确认。

日历中带圆点的日期表示本机存在可用于重建的数据。范围可以包含没有圆点的日期，但实际只处理有本机数据的日期。

### 状态提示

| 提示                           | 含义                                     |
| ------------------------------ | ---------------------------------------- |
| 「未选择重建日期范围」         | 尚未开始选择                             |
| 「选择结束日期」               | 已选择开始日期，等待选择结束日期         |
| 「已选择 X 天」                | 日期范围已完成，范围中有可重建数据       |
| 「没有可重建的本地数据」       | 所选范围没有可用的本机 Hook 记录         |
| 「共处理 X 天，包含 X 条数据」 | 本机重建完成                             |
| 「跳过 X 条无效数据」          | 有少量记录无法读取，其余内容已完成重建   |
| 「云端替换将在同步可用后继续」 | 本机已完成，跨设备数据会在同步恢复后更新 |
| 「重建失败」                   | 本次没有完成，请根据后续错误信息处理     |

如果跨设备同步已开启，重建结果会更新当前设备在所选日期的同步数据，不影响其他设备或范围外日期。

## 9. 跨设备同步

### 同步内容

跨设备同步用于在多台 Mac 上合并 Hook 的每日工作流统计，例如会话、轮次、模型和工具使用次数。Token 用量与实时任务不会跨设备同步。

### 开启条件

- 「CodexBar Hook」已开启
- 「跨设备同步」已开启
- 当前 Mac 已登录可用的 iCloud 账号
- 多台 Mac 使用同一个 iCloud 账号

### 开启步骤

1. 先开启「CodexBar Hook」。
2. 确认 macOS 已登录 iCloud。
3. 开启「跨设备同步」。
4. 等待设置中出现「最近同步」时间，或在菜单底部查看 iCloud 图标。

首次开启后，历史统计需要一些时间完成合并。保持 CodexBar 运行即可，无需反复开关。

### 同步图标

| 图标                | 含义                     | 建议操作                                             |
| ------------------- | ------------------------ | ---------------------------------------------------- |
| 普通 iCloud         | 同步已开启               | 悬停查看最近同步时间；显示「暂无同步记录」时继续等待 |
| 带斜杠的 iCloud     | 同步未开启或没有实际生效 | 检查 Hook、同步开关和 iCloud 登录状态                |
| 带旋转箭头的 iCloud | 正在同步                 | 等待完成                                             |
| 带感叹号的 iCloud   | 最近一次同步失败         | 悬停查看原因，按网络、账号或服务状态处理             |

### 常见问题

#### 为什么同步开关是灰色的？

先开启 Hook，并确认当前 Mac 已登录 iCloud。Hook 正在更新或 iCloud 状态尚未确认时，也可能暂时不可操作。

#### 为什么显示「同步不可用」？

常见原因包括 iCloud 未登录、账号受限、网络不可用或服务暂时不可用。先打开 macOS 系统设置确认 iCloud，再稍后返回 CodexBar。

#### 为什么另一台 Mac 没有马上出现数据？

确认两台 Mac 使用同一 iCloud 账号，并且都开启 Hook 和跨设备同步。首次合并或历史数据较多时需要等待后续同步完成。

#### 同步失败后需要重新开关吗？

通常不需要。网络或服务恢复后，CodexBar 会在后续刷新中继续尝试。长期失败时再检查 iCloud 登录和系统网络。

#### 为什么两台 Mac 的 Token 热力图不同？

跨设备同步只合并 Hook 工作流统计，不同步 Token 用量，因此每台 Mac 的 Token 数据仍来自各自本机 Codex。

## 10. 系统通知、Codex TUI 通知与触觉反馈

### 开启步骤

1. 打开设置。
2. 开启「系统通知」。
3. 在 macOS 弹窗中允许 CodexBar 发送通知。
4. 点击「系统通知」右侧的滑杆图标。

如果通知权限被拒绝，设置中会显示提示和「打开系统设置」按钮。允许通知后，返回 CodexBar 即可继续配置。

| 任务触觉反馈   | 任务进入等待批准或确认结束    | 需要 Hook 和支持的输入设备          |
| Codex TUI 通知 | 控制 Codex CLI 自身的终端通知 | 修改后重新启动正在运行的 Codex 会话 |

任务完成、任务等待和任务触觉选项依赖 Hook。Hook 关闭时，它们会置灰，但会保留此前选择。

CodexBar 系统通知都可以独立选择声音，默认使用 macOS 系统通知声；选择「静音」时只显示通知。声音菜单将选项分为 14 个经典提示音和 17 个现代提示音，包括 Basso、Glass、Sosumi、Antic、Droplet、Portal、Received Message 等。打开声音菜单并选择任意声音时会立即试听；也可以点击声音右侧的播放按钮重复试听当前选项，选择「静音」时该按钮不可用。声音偏好会在通知关闭或 Hook 暂停时保留；Codex TUI 通知由 Codex CLI 自己播放，不使用这里的声音设置。

### 图标与状态

| 图标或状态                   | 含义                           |
| ---------------------------- | ------------------------------ |
| 「系统通知」右侧滑杆         | 打开通知子选项                 |
| 通知声音菜单                 | 选择声音并立即试听             |
| 通知声音右侧播放按钮         | 重复试听当前声音；静音时不可用 |
| Codex TUI 通知旁的小进度圈   | 正在读取或保存设置             |
| Codex TUI 通知旁的橙色感叹号 | 读取或保存失败；悬停可查看原因 |
| 「打开系统设置」按钮         | macOS 尚未授权 CodexBar 通知   |

点击 CodexBar 发出的系统通知，会尝试打开主菜单面板，方便继续查看任务或额度状态。

### 常见问题

#### 为什么开启后仍收不到通知？

依次确认：

1. 「系统通知」总开关已开启。
2. macOS 系统设置允许 CodexBar 通知。
3. 对应通知子选项已开启。
4. 额度数据正常，或任务类通知所需的 Hook 已开启。
5. 任务耗时达到所选完成通知阈值。

#### 为什么短任务没有完成通知？

任务完成通知只提醒达到所选时长的任务。默认阈值为 1 分钟，可改为 30 秒、2 分钟或 5 分钟。

#### 为什么短暂显示等待批准，却没有通知？

只有确实需要用户处理、并且仍处于等待状态的任务才会通知。自动处理或很快恢复运行的请求不会产生过期提醒。

#### 为什么等待通知从通知中心消失了？

当任务恢复运行、完成或终止后，对应等待通知会自动撤回，避免留下已经失效的提示。

#### 为什么没有触觉反馈？

确认「系统通知」「任务触觉反馈」和 Hook 都已开启。触觉效果还取决于 Mac、触控板、辅助功能和系统偏好，部分设备不会产生明显反馈。

#### 为什么 Codex TUI 通知旁有感叹号？

把鼠标停在感叹号上查看原因。确认 Codex 可以正常使用后重试；保存成功后，重新启动已打开的 Codex 会话。

### 设置全局快捷键

默认快捷键为 `⌘⇧W`。

修改步骤：

1. 点击叉号图标清除当前快捷键。
2. 点击「未设置」。
3. 按下新的按键组合。

快捷键至少需要 `Control`、`Option`、`Shift`、`Command` 中的两个修饰键。

| 图标或操作 | 作用                 |
| ---------- | -------------------- |
| 回转箭头   | 恢复默认快捷键 `⌘⇧W` |
| 叉号       | 清除当前快捷键       |
| `Esc`      | 取消本次录制         |

如果提示「至少需要两个修饰键」，请增加修饰键后重试。如果提示「不可使用系统快捷键」，请选择未被 macOS 保留的组合。注册失败时，CodexBar 会恢复之前的可用设置并显示原因。

### 开机自动启动失败

确认 CodexBar 已放在最终安装位置，并检查 macOS 是否允许登录项。移动 App 后，关闭再开启「开机自动启动」，让系统记录新位置。

### 退出 CodexBar

可以右键菜单栏图标选择「退出」，也可以在设置底部点击红色的「退出 CodexBar」。

## 12. 日志、版本与更新

### 使用日志

打开方式：

- 右键菜单栏图标，选择「日志」
- 主菜单面板打开时按 `⌘L`

日志适合排查未登录、初始化失败、刷新超时、Hook 验证和设置失败。

| 日志标签 | 颜色 | 含义                       |
| -------- | ---- | -------------------------- |
| 进行     | 橙色 | 正在等待结果               |
| 完成     | 绿色 | 已收到正常结果             |
| 错误     | 红色 | 请求或操作失败             |
| 请求     | 蓝色 | 已发出不需要等待结果的操作 |

点击日志行可以展开摘要；点击「预览」查看完整内容，点击「复制」复制内容。顶部数字表示当前日志条数，「清空」会删除当前运行期间的日志列表。

关闭日志窗口不会立即清空记录；退出 CodexBar 后，本次运行日志会消失。

### 查看 Codex 版本

设置中的「Codex 版本」会列出：

| 图标     | 来源                 |
| -------- | -------------------- |
| 终端     | 全局安装的 Codex CLI |
| App 标记 | Codex App 内置的 CLI |

绿色「当前使用」表示 CodexBar 当前连接的来源。橙色「已更新至」表示磁盘上已有更新版本，但当前运行中的 Codex 仍可能是较早版本；重新启动 Codex 后再刷新即可确认。

点击路径可以复制，复制成功后会短暂显示「已复制」。

### 更新 CodexBar

- 开启「自动检查更新」后，CodexBar 会定期检查新版本。
- 点击设置底部「检查更新」可以立即手动检查。
- 发现更新后，「CodexBar 版本」右侧会出现向下箭头按钮。
- 菜单面板底部也会显示新版本提示，双击即可开始更新。

| 更新提示           | 含义                                                     |
| ------------------ | -------------------------------------------------------- |
| 「正在检查更新」   | 正在查询新版本                                           |
| 「没有可用更新」   | 当前已是最新版本                                         |
| 「发现新版本」     | 可以点击更新按钮安装                                     |
| 「检查更新失败」   | 本次检查没有完成，请稍后重试                             |
| 「未配置更新资源」 | 当前安装版本不支持内置更新，建议从 Releases 重新下载安装 |

## 13. 常见问题速查

| 现象                     | 优先检查                                             |
| ------------------------ | ---------------------------------------------------- |
| 找不到 Dock 图标或主窗口 | CodexBar 只显示在菜单栏，这是正常设计                |
| 菜单栏人物带叉           | 打开菜单查看「未登录」或「初始化失败」               |
| 主面板显示「暂无数据」   | 确认 Codex 已登录，手动刷新并查看日志                |
| 额度或热力图变淡         | 当前显示的是较早缓存，等待或手动刷新                 |
| 菜单栏没有额度竖条       | 开启「菜单栏额度指示」，并检查所选窗口是否有数据     |
| 看不到手动重置次数       | 当前账号没有可用机会，或数据尚未刷新                 |
| 热力图没有工作流统计     | 开启 Hook，并确认该日期有 Hook 记录                  |
| 活动卡片没有出现         | 同时开启 Hook 和「主面板任务中心」                   |
| 点击活动卡片没有反应     | 当前没有可展示任务，或主数据尚未加载                 |
| 任务一直显示运行中       | 任务可能没有正常留下结束状态，等待后续活动或自动过期 |
| 合盖后任务仍然停止       | 检查防休眠开关、Hook 状态和 CodexBar 后台项目授权    |
| 跨设备同步开关置灰       | 先开启 Hook，并确认 iCloud 可用                      |
| iCloud 图标带感叹号      | 悬停查看网络、账号或服务错误                         |
| 收不到系统通知           | 检查总开关、macOS 权限、子选项和 Hook 依赖           |
| 没有触觉反馈             | 检查三个开关，并确认设备支持触觉                     |
| 快捷键无法设置           | 先清除原快捷键，使用至少两个修饰键的新组合           |
| 设置显示两个 Codex 版本  | 查看绿色「当前使用」标记确认实际来源                 |
| 更新检查失败             | 稍后重试，或从 Releases 手动下载安装                 |

如果速查表仍无法解决问题，请打开日志，找到最新红色「错误」记录，再结合对应功能章节处理。

## 14. 隐私与数据范围

CodexBar 以本机处理为主：

- 账号、额度和 Token 用量在本机读取和展示。
- Hook 原始记录保存在当前 Mac，默认保留最近 210 天。
- 实时任务只在当前 App 运行期间用于状态展示。
- 防休眠 helper 只在本机切换系统休眠设置并维护恢复哨兵，不访问网络或任务内容。
- 菜单面板只显示项目名称，不显示完整工作目录、会话编号或轮次编号。
- CodexBar 不展示提示词、回复、推理内容、工具内容或审批内容。

跨设备同步完全可选。开启后，只通过当前 iCloud 账号的私有数据库同步每日工作流聚合；不会同步 Codex 账号、额度、Token 用量、原始 Hook 记录、实时任务、请求日志或认证信息。

CodexBar 只有在以下用户可见功能中使用网络：

- 查询手动重置机会的过期时间
- 检查和下载 CodexBar 更新
- 用户主动开启的跨设备同步

关闭 Hook 会停止记录新的工作流活动；关闭跨设备同步会停止后续同步。更详细的数据说明见 [Codex Hook 文档](CodexHook.md) 和 [跨设备同步文档](CrossDeviceSync.md)
