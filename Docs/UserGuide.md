## 1. 快速开始

### 使用要求

- macOS 15.0 或更高版本。
- 已安装 Codex CLI 或 Codex.app。
- 已在 Codex 中完成登录。

CodexBar 是菜单栏 App，不显示 Dock 图标，也没有传统的主窗口。启动后请在屏幕顶部菜单栏查找 CodexBar 图标。

### 第一次使用建议

1. 左键点击菜单栏图标，确认账号、额度和 Token 用量能够正常显示。
2. 右键点击菜单栏图标并打开「设置」。
3. 按需要开启「开机自动启动」和「自动检查更新」。
4. 如果需要工作流统计、实时任务状态或任务通知，开启「启用 Codex Hook」。
5. 如果需要在多台 Mac 之间合并 Hook 统计，再开启「跨设备同步」。
6. 如果需要提醒，开启「系统通知」，再点击通知行右侧的滑杆图标配置具体通知。

## 2. 所有入口与快捷操作

下面这些交互有一部分没有文字按钮，第一次使用时容易错过。

| 位置                             | 操作                                | 结果                                                   |
| -------------------------------- | ----------------------------------- | ------------------------------------------------------ |
| 菜单栏图标                       | 左键点击                            | 打开或关闭主菜单面板                                   |
| 菜单栏图标                       | 右键点击，或按住 `Control` 左键点击 | 打开设置、日志和退出菜单                               |
| 任意 App 中                      | 默认按 `⌘⇧W`                        | 打开或关闭主菜单面板                                   |
| 任意位置                         | 按 `⌘,`                             | 打开 CodexBar 设置窗口                                 |
| 主菜单面板打开时                 | 按 `⌘L`                             | 关闭菜单面板并打开日志窗口                             |
| 账号卡片头像                     | 双击                                | 立即刷新账号、额度和用量                               |
| 账号邮箱                         | 双击                                | 模糊或恢复邮箱显示                                     |
| 活动卡片                         | 单击                                | 打开或关闭并发任务中心；需要开启 Hook 且存在可展示任务 |
| `重置次数: N`                    | 单击                                | 查看各批手动重置机会的过期时间和数量                   |
| Token 热力图方块                 | 鼠标悬停                            | 查看当天 Token 和 Hook 工作流统计                      |
| 菜单面板底部同步图标             | 鼠标悬停                            | 查看同步未开启、正在同步、失败或最近同步时间           |
| 菜单面板底部更新提示             | 双击                                | 立即开始安装可用更新                                   |
| 设置中的「系统通知」右侧滑杆图标 | 单击                                | 展开具体通知和触觉选项                                 |
| 设置中的 Codex 安装路径          | 单击                                | 复制路径，短暂显示「已复制」                           |
| 日志列表中的一行                 | 单击                                | 展开请求、响应或错误摘要                               |
| 日志展开内容                     | 点击「预览」或「复制」              | 查看或复制完整内容                                     |

点击菜单面板和侧边详情面板之外的区域会关闭菜单面板，这是菜单栏工具的正常行为。

## 3. 看懂菜单栏图标

### 账号状态

- 正常人物图标：账号数据可用。
- 带叉图标：未登录、初始化失败，或当前快照不可信。
- 将鼠标停在图标上可以查看账号异常、实时任务和额度窗口的摘要。

### 菜单栏额度指示

设置中的「菜单栏额度指示」开启后，图标左侧会显示当前所选额度窗口的剩余比例。可以在同一设置行切换要显示的额度窗口。

颜色按剩余额度分档：

| 剩余额度   | 颜色含义 |
| ---------- | -------- |
| 80% 及以上 | 充足     |
| 60%–79%    | 较充足   |
| 40%–59%    | 需要留意 |
| 20%–39%    | 较低     |
| 低于 20%   | 紧张     |

额度窗口暂时没有可信数据时，菜单栏不会显示这条额度指示。

### 实时任务状态点

开启 Codex Hook 后，人物图标右下角可能出现状态点：

- 橙色：有任务正在等待批准。
- 蓝色：有任务正在运行。
- 绿色：任务刚刚完成，绿色状态保留约 30 秒。
- 无状态点：当前没有等待或运行任务，也没有处于绿色高亮期的完成任务。

状态点只在主面板额度快照可用时按上述任务状态绘制；活动卡片显示「暂无数据」时不显示状态点。

当多个状态同时存在时，显示优先级为：等待批准、运行中、刚完成、空闲。

## 4. 使用菜单面板

### 账号卡片

账号卡片显示当前账号、订阅类型和刷新状态。

- 双击头像可以立即刷新。
- 双击邮箱可以模糊邮箱，适合共享屏幕或截图时临时隐藏账号信息。
- 刷新中的小进度指示只表示正在请求本机 Codex app-server。

CodexBar 默认每 60 秒自动刷新一次。菜单面板底部「数据更新时间」左侧的蓝色圆环表示距离下一次刷新还有多久。

### 活动卡片和任务中心

活动卡片只在 Codex Hook 开启时出现。它优先显示：

1. 等待批准的任务。
2. 正在运行的任务。
3. 最近完成的任务。
4. 最近终止的任务。
5. 暂无活动。

右侧 `+N` 表示还有其他正在运行或等待批准的任务。点击活动卡片会打开任务中心，完整列出：

- 等待确认。
- 运行中。
- 最近完成。
- 最近终止。

「完成」只表示 Codex 已确认该轮结束，不代表任务结果一定成功。「终止」表示任务没有按正常完成路径结束，也不会触发绿色状态或完成通知。

最近完成和最近终止记录保留约 10 分钟。任务中心会在菜单侧面展开，右侧空间不足时自动改到左侧，顶边优先与活动卡片对齐。点击时如果卡片布局尚未稳定，任务中心会等待一次布局更新后重试；仍然无法取得有效位置时，才在主面板旁垂直居中。面板高度随列表内容变化，底部与最后一个项目保持固定留白且不会低于主面板底边；内容达到可用高度上限后改为内部滚动。

### 额度和重置时间

额度区域按 Codex 返回的时间窗口展示：

- 剩余百分比。
- 分段额度条。
- 下一次重置时间。

如果某一轮刷新失败，但之前有同账号的可用数据，CodexBar 会暂时显示旧缓存。此时额度或用量区域会变淡，表示数据可能不是最新值。

如果 Codex 返回可用的手动重置机会，主额度标题右侧会出现 `重置次数: N`。点击后可以查看：

- 各过期时间下有多少次机会。
- 过期时间未知时显示「未知过期时间」。

CodexBar 只查询重置机会和过期时间，不会代替用户执行额度重置。

### Token 摘要和近 30 周热力图

用量区域包括：

- 全时累计 Token。
- 单日峰值。
- 当前连续使用天数。
- 最长连续使用天数。
- 最长任务耗时。
- 近 30 周每日 Token 热力图。

将鼠标移动到热力图方块上，会在菜单侧面显示当天详情。蓝色越深，表示当天 Token 用量相对越高。

Hook 关闭时，详情主要显示日期、Token 和用量强度。Hook 开启后，还会显示最热模型、会话总数、对话轮次、子智能体、工具调用、权限请求和上下文压缩次数。

这些工作流指标表示：

| 指标       | 通俗解释                                                  |
| ---------- | --------------------------------------------------------- |
| 最热模型   | 当天 Hook 事件中出现次数最多的模型，不代表消耗 Token 最多 |
| 会话总数   | 当天识别到的不同 Codex 会话数量                           |
| 对话轮次   | 当天识别到的不同任务轮次数量                              |
| 子智能体   | 子智能体启动或结束事件归一后的数量                        |
| 调用工具   | 工具调用开始或结束事件归一后的数量                        |
| 权限请求   | Codex 请求用户批准操作的次数                              |
| 上下文压缩 | 上下文压缩开始或结束事件归一后的数量                      |

Hook 统计只从开启后开始记录，不能补出开启前的工作流历史。Token 数据和 Hook 统计来源不同，因此某一天可能有 Token，但没有 Hook 明细；也可能当天 Hook 已有事件，但 Token 桶尚未返回。

### 菜单底部状态

菜单底部包含三类信息：

- 数据更新时间和 60 秒刷新倒计时。
- 跨设备同步状态图标；悬停可查看详情。
- 可用更新提示；双击提示可以开始更新。

## 5. 设置 CodexBar

通过右键菜单中的「设置」或 `⌘,` 打开设置窗口。

| 设置项          | 作用                                            | 注意事项                               |
| --------------- | ----------------------------------------------- | -------------------------------------- |
| 开机自动启动    | 登录 macOS 后自动启动 CodexBar                  | 移动 App 后建议重新关闭再开启一次      |
| 自动检查更新    | 允许 Sparkle 自动检查新版本                     | 关闭后仍可手动检查                     |
| 菜单栏额度指示  | 在图标左侧显示所选额度窗口                      | 没有可用数据时自动隐藏                 |
| 启用 Codex Hook | 开启工作流统计、活动卡片和任务提醒              | 会修改当前用户的 `~/.codex/hooks.json` |
| 跨设备同步      | 通过 iCloud private database 合并 Hook 日聚合   | 需要 Hook 已开启且 iCloud 可用         |
| 系统通知        | 控制 CodexBar 通知和任务触觉反馈总开关          | 首次开启需要系统授权                   |
| 使用快捷键      | 设置全局打开/关闭菜单面板的快捷键               | 至少需要两个修饰键                     |
| Codex 版本      | 查看全局 CLI、Codex.app 内置 CLI 和当前使用来源 | 点击路径可以复制                       |
| CodexBar 版本   | 查看更新状态和当前版本                          | 有更新时可点击右侧更新按钮             |

### 修改全局快捷键

默认快捷键是 `⌘⇧W`。

如果已经设置快捷键，需要先点击叉号清除，再点击「未设置」开始录制新的组合。快捷键至少包含两个修饰键，且不能使用 `⌘Space`、`⌘Tab` 等系统保留组合。

- 按 `Esc` 取消本次录制。
- 点击回转箭头恢复默认快捷键。
- 如果注册失败，设置行下方会显示原因，原快捷键会被恢复。

### 配置通知子选项

开启「系统通知」后，点击该行右侧的滑杆图标，可以分别设置额度预警、额度重置、任务完成、任务等待、任务触觉、重置次数临期提醒和 Codex TUI 通知。具体说明见[通知与触觉反馈](#8-通知与触觉反馈)。

## 6. Codex Hook 与实时任务

### Hook 能带来什么

开启 Hook 后，CodexBar 可以：

- 统计会话、对话轮次、工具调用、权限请求、上下文压缩和子智能体事件。
- 在活动卡片和任务中心显示正在运行、等待批准、最近完成和最近终止任务。
- 发送任务等待和长任务完成通知。
- 在支持的设备上请求任务触觉反馈。

### Hook 会读取什么

CodexBar Hook 记录事件类型、时间、模型、权限模式、会话和轮次标识、工具名以及工作目录。UI 只展示工作目录最后一级名称，不展示完整路径、会话 ID 或轮次 ID。

为补齐缺失的开始、完成或中断信号，主 App 还会只读当前活跃任务对应的本机 Codex session rollout。它只解析生命周期字段，不提取提示词、回复、推理或工具内容。

### Hook 配置提示是什么意思

| 提示                      | 含义和处理建议                                                           |
| ------------------------- | ------------------------------------------------------------------------ |
| `Codex 配置已禁用 Hook`   | Codex 全局配置关闭了 Hook；先在 Codex 配置中启用 Hook                    |
| `hooks.json 文件格式错误` | `~/.codex/hooks.json` 不是有效格式；修复文件后重试                       |
| `CodexBar Hook 已被禁用`  | Hook 存在，但 Codex 报告它未启用                                         |
| `CodexBar Hook 未被信任`  | Codex 没有信任当前命令；重新开关 Hook，仍失败时查看日志                  |
| `CodexBar Hook 已不完整`  | 部分需要的事件没有安装；重新关闭并开启 Hook                              |
| `CodexBar Hook 意外来源`  | 生效的 Hook 不是来自预期的全局配置文件                                   |
| `无法验证 Codex Hook`     | 配置可能已经写入，但 app-server 验证失败；查看日志中的 `hooks/list` 请求 |
| `设置 Codex Hook 失败`    | 开启前检查或写入失败；根据下方错误及日志排查                             |

CodexBar 只增删属于当前 CodexBar 可执行文件的 Hook，不会删除其他 App 或用户自己的 Hook。

### 关闭 Hook 或移动 App

关闭 Hook 会停止记录新事件、隐藏 Hook 统计和活动卡片，并清空当前进程中的实时任务状态，但不会删除已经保存在本机的历史文件。以后重新开启 Hook 时，已有聚合仍可继续使用。

Hook 命令包含 CodexBar 当前可执行文件的完整路径。如果准备把 `CodexBar.app` 移到其他目录，建议先在旧位置关闭 Hook，移动后再重新开启。已经移动且旧 Hook 无法执行时，需要检查 `~/.codex/hooks.json` 中是否仍有指向旧路径的 CodexBar 命令。

不要同时保留指向不同 CodexBar 安装位置的 Hook。Codex 会分别调用每条生效命令，同一个事件可能被追加多次，导致统计重复；其他位置的 CodexBar 还可能改写共享的维护状态，使当天的 generation 再次变化。移动或替换 App 后应先移除原路径 Hook，再只启用最终安装位置的版本。

### Codex 被关闭后为什么任务仍显示运行中

如果 Codex 正常写入 `Stop`、`task_complete` 或 `turn_aborted`，CodexBar 可以识别完成或终止。

如果 Codex 被强制关闭、进程崩溃、终端直接退出或电脑断电，而且没有留下终态事件，CodexBar 无法立即确定任务是否真的结束。此时：

- 同一 session 后续出现新 Prompt，旧任务会立即退出运行列表，并等待约 5 秒确认真实终态；仍无终态时记为最近终止。
- 始终没有任何后续事件，任务最多可能保留 24 小时。
- 重新启动 CodexBar 或重新开启 Hook 后，最近 24 小时事件可能再次恢复这条无终态任务。

当前版本没有单任务「手动移除」功能。单纯长时间没有事件也不能安全地自动判定终止，因为任务可能正在长时间调用工具、等待输入或经历系统休眠。

## 7. 跨设备同步

### 开启条件

跨设备同步同时需要：

- Codex Hook 已开启。
- 设置中的「跨设备同步」已开启。
- 当前 Mac 已登录可用的 iCloud 账号。

如果开关呈灰色或显示「同步不可用」，请先确认 Hook 状态和 macOS 的 iCloud 登录状态。

### 同步什么

同步使用当前 iCloud 账号的 CloudKit private database，只上传按设备、按天生成的脱敏聚合数据，用于合并热力图中的工作流统计。

同一台 Mac 同一天、同一 generation 的本地聚合和 iCloud 副本不会重复相加，通常显示事件数更完整的一份。如果当天事件文件被完整删除或清空，CodexBar 能确认后续事件属于新的独立 generation，因此新统计会与已有云端贡献相加；如果文件被替换成一份非空且来源不明确的数据，CodexBar 会继续使用已有云端记录，不自动覆盖或叠加，避免重复统计。

直接删除某个历史日期的本机 events 文件不会同步删除 daily 聚合或云端记录，因此页面通常仍会显示原来的统计。如果连对应 daily 行也删除，开启同步时页面会回退使用已缓存的云端贡献；关闭同步或云端没有副本时，该日期才会消失。

不会上传：

- Codex 账号和额度。
- Token 用量。
- 原始 Hook 事件。
- 会话 ID 和轮次 ID。
- 实时任务状态。
- 请求日志和 Codex 认证文件。

### 看懂同步状态

菜单面板底部的 iCloud 图标表示同步状态，悬停可以查看文字：

- 带斜杠：同步未开启或未实际生效。
- 旋转箭头：正在同步。
- 感叹号：最近一次同步失败。
- 普通 iCloud：同步已开启；悬停显示最近同步时间或「暂无同步记录」。

同步在 Hook 统计维护后触发。网络或服务暂时失败时不需要反复开关，后续刷新会继续重试尚未成功的日期。

## 8. 通知与触觉反馈

### 开启步骤

1. 打开 CodexBar 设置。
2. 开启「系统通知」。
3. 在 macOS 授权提示中允许通知。
4. 点击通知行右侧的滑杆图标，配置具体提醒。

如果系统权限被拒绝，设置页会显示提示和「打开系统设置」按钮。

### 可用通知

| 选项             | 触发条件                                           | 配置或频率                       |
| ---------------- | -------------------------------------------------- | -------------------------------- |
| 额度预警通知     | 可信额度从阈值上方跌到阈值或以下                   | 5%、10%、25%，默认 10%           |
| 额度重置通知     | 已发生消耗的额度窗口恢复到 100%                    | 提供重置时间时，同周期提醒一次   |
| 任务完成通知     | Hook 任务确认完成且耗时达到阈值                    | 30 秒、1、2、5 分钟，默认 1 分钟 |
| 任务等待通知     | 用户审批模式下，任务在一批事件处理结束后仍等待批准 | 无                               |
| 任务触觉反馈     | 任务进入等待批准或确认结束                         | 需要 Hook；服从通知总开关        |
| 重置次数临期通知 | 手动重置机会将在 7 天内过期                        | 最多每 24 小时提醒一次           |
| Codex TUI 通知   | Codex CLI TUI 发送终端通知                         | 与 `[tui] notifications` 联动    |

任务完成、任务等待和任务触觉选项需要 Hook。Hook 关闭时，这些选项会显示为关闭并置灰，但不会丢失用户原来的偏好。

「Codex TUI 通知」读取用户级 `~/.codex/config.toml`：`[tui] notifications = false` 时显示为关闭。切换开关会通过本机 Codex app-server 写入 `tui.notifications = false/true`，不会修改顶层 `notify` 外部回调。已经运行的 Codex CLI 需要重新启动会话后采用新设置；读取或写入失败时，选项旁显示警告图标，悬停可查看原因。

当前 App 进程发出的等待批准通知会跟随 Monitor 中的任务状态；任务恢复运行、完成、终止或以其他方式离开等待状态后，通知会自动从通知中心移除，不影响其他仍在等待的并发任务。

触觉反馈是否真的发生、震感强弱和形式由 Mac、触控板、辅助功能及系统偏好决定。CodexBar 请求了触觉，不代表所有设备都能产生明显反馈。

点击 CodexBar 发出的系统通知会尝试打开主菜单面板，方便继续查看当前状态。

## 9. 日志、版本与更新

### 打开日志

- 右键菜单栏图标，选择「日志」。
- 主菜单面板打开时按 `⌘L`。

日志记录 CodexBar 与本机 app-server 的请求状态，适合排查「未登录」「初始化失败」、刷新超时、Hook 验证和接口兼容问题。

使用方法：

- 点击一行展开。
- 点击「预览」打开完整内容；JSON 会格式化并高亮。
- 点击「复制」复制完整请求、响应或错误。
- 点击顶部「清空」删除当前进程内的日志列表。

提交问题前建议先查看日志，但分享日志前仍应自行检查内容是否适合公开。

### Codex 版本

设置中的「Codex 版本」会同时展示：

- 全局安装的 Codex CLI。
- Codex.app 内置的 CLI。
- 当前 app-server 实际使用的来源。
- 磁盘安装版本与当前运行版本是否一致。

点击安装路径可以复制，便于确认 CodexBar 实际连接了哪个 Codex。

### 更新 CodexBar

- 开启「自动检查更新」后，Sparkle 会定期检查新版本。
- 可以随时点击设置底部的「检查更新」。
- 有可用更新时，设置中的版本行会出现更新按钮。
- 菜单面板底部出现更新提示时，可以双击提示开始更新。

## 10. 常见问题

### A. 启动、账号与数据

#### 为什么启动后没有 Dock 图标或主窗口？

这是正常设计。CodexBar 是纯菜单栏 App，请从屏幕顶部菜单栏打开。

#### 为什么菜单栏图标显示叉号？

通常表示 Codex 未登录、CodexBar 初始化 app-server 失败，或当前数据不可信。先打开 Codex CLI 或 Codex.app 确认已经登录，然后双击 CodexBar 账号头像刷新；仍失败时查看日志。

#### 「未登录」应该怎么处理？

在 Codex CLI 或 Codex.app 中完成登录，再回到 CodexBar 双击头像刷新。CodexBar 不提供独立登录流程。

#### 「初始化失败」应该怎么处理？

依次检查：

1. Codex CLI 或 Codex.app 是否仍安装在磁盘上。
2. 设置中的「Codex 版本」能否找到安装路径。
3. 点击路径确认当前使用来源是否符合预期。
4. 打开日志查看是找不到可执行文件、超时、断连还是接口不兼容。
5. 更新 Codex CLI、Codex.app 和 CodexBar 后重试。

#### 为什么只显示「暂无数据」？

账号可能已经识别，但本轮没有返回可展示的额度或用量。等待下一次自动刷新，或双击头像手动刷新；日志中会保留更具体的请求结果。

#### 为什么额度或热力图突然变淡？

变淡表示本轮刷新失败，CodexBar 正在显示同账号的旧缓存。缓存仍可参考，但可能不是最新值。

#### 数据多久刷新一次？

账号、额度和 Token 用量默认每 60 秒刷新一次。双击头像可以立即刷新，并重新开始 60 秒倒计时。

### B. 点击入口和菜单行为

#### 哪些地方可以点击或悬停？

最容易错过的入口是：活动卡片、`重置次数: N`、热力图方块、通知行右侧滑杆图标、Codex 安装路径，以及日志行。完整列表见[所有入口与快捷操作](#2-所有入口与快捷操作)。

#### 为什么点击活动卡片没有反应？

任务中心只有在以下条件同时满足时才能打开：

- Hook 已开启。
- 账号和主数据快照已经加载。
- 当前存在运行、等待、最近完成或最近终止任务。

显示「暂无数据」或「暂无 Codex 活动」时不会打开空任务中心。

#### 为什么热力图详情不能点击？

热力图详情是跟随鼠标悬停的只读侧边面板，不接收点击。把鼠标移回目标日期即可重新显示。

#### 为什么点击菜单外部后面板关闭了？

这是菜单栏工具的预期行为。任务中心和重置次数面板属于菜单面板的侧边区域，点击它们内部不会关闭主菜单。

#### 怎么隐藏截图里的邮箱？

双击账号卡片中的邮箱即可模糊，再双击一次恢复。账号变化后模糊状态会自动重置。

### C. 额度、重置次数和热力图

#### 为什么菜单栏没有额度竖条？

检查设置中的「菜单栏额度指示」是否开启，以及所选窗口是否有可信数据。窗口没有返回数据时，指示会自动隐藏。

#### 为什么看不到 `重置次数: N`？

只有 Codex 返回大于零的可用手动重置机会时才显示。CodexBar 不会自行预测或创建重置机会。

#### 为什么重置次数详情显示「未知过期时间」？

CodexBar 已知道可用次数，但读取过期时间的只读请求失败或没有返回有效时间。次数本身仍可能有效。

#### 为什么热力图中的今天显示 `--`？

Hook 已记录今天的工作流事件，但 Token 用量接口还没有返回今天的 bucket 时，会显示 `--`。这不代表 Hook 数据丢失。

#### 为什么 Hook 统计和 Token 数对不上？

两者来自不同数据源：Token 来自本机 app-server 用量接口，工作流统计来自 Codex Hook。它们的更新时间、保留范围和统计口径不同，不应逐项一一对应。

### D. Hook 与实时任务

#### 为什么开启 Hook 后看不到以前的统计？

Hook 只能从开启后开始记录事件，无法还原此前没有写入的工作流历史。

#### 关闭 Hook 会删除以前的统计吗？

不会。关闭 Hook 只停止新事件记录、同步调度和实时任务监测，本机历史文件仍然保留。重新开启后可以继续显示已有统计。

#### 移动 CodexBar.app 后 Hook 不工作了怎么办？

Hook 保存的是 App 可执行文件的完整路径。将 App 移回原位置后先关闭 Hook，再把 App 移到最终位置并重新开启；或者检查 `~/.codex/hooks.json`，移除指向旧 CodexBar 路径的命令后重新开启。

#### 为什么有任务在 Codex 中运行，CodexBar 却没有显示？

可能原因包括：Hook 未开启或不完整、任务开始事件没有送达、Hook 配置未被信任、主菜单数据尚未加载，或正在使用的 Codex 版本不支持所需事件。先查看 Hook 行提示，再检查日志。

#### 为什么任务显示「正在运行」但没有精确耗时？

任务可能是从工具或权限事件恢复出来的，缺少可信的 Prompt 起点；匿名任务也不会猜测精确耗时。CodexBar 会保留运行状态，但显示「正在运行」而不是不可靠的时长。

#### 为什么 Codex 已经关闭，任务仍显示运行中？

强制关闭或崩溃可能来不及写入结束事件。没有终态时 CodexBar 无法立即判断，任务最多可能保留 24 小时。详见[Codex 被关闭后为什么任务仍显示运行中](#codex-被关闭后为什么任务仍显示运行中)。

#### 能否手动清除一条卡住的运行任务？

当前版本不能。重新启动或重新开启 Hook 也可能从最近事件中恢复它。同一 session 出现新 Prompt 后，旧任务通常会在约 5 秒内归入最近终止；否则等待 24 小时活动过期。

#### 为什么「最近终止」没有发送完成通知？

终止不等于完成。终止记录只用于说明任务不再处于正常运行路径，不触发绿色状态、完成通知或完成触觉反馈。

#### 为什么多个任务只在卡片上看到一个？

卡片只展示优先级最高的一项，右侧 `+N` 表示其他活动任务。点击卡片打开任务中心可以查看完整列表。

### E. 跨设备同步

#### 为什么跨设备同步开关不可用？

先开启 Hook，再确认 macOS 已登录 iCloud 且 CloudKit 账号状态可用。任一条件不满足时，同步不会实际生效。

#### 同步会上传 Token、提示词或会话 ID 吗？

不会。跨设备同步只上传脱敏的每日 Hook 聚合，不上传 Token 用量、提示词、回复、原始事件、会话 ID 或轮次 ID。

#### 为什么刚开启同步没有立刻看到另一台 Mac 的数据？

首次开启会安排历史聚合回填，并在后续统计维护和刷新中分批上传、下载。请保持 Hook 与同步开启，并查看菜单底部同步图标和设置中的最近同步时间。

#### 同步失败后需要重新开关吗？

通常不需要。网络、账号或 CloudKit 服务暂时失败时，后续刷新会重试未完成日期。长期失败时检查 iCloud 登录状态和系统网络。

#### 在 CloudKit Dashboard 删除记录后为什么没有自动传回来？

云端删除会从本机同步缓存移除，但不会清除已经确认上传的本机日期 hash。如果该日的本机聚合没有变化，下一轮不会立即重复上传；只有本机内容变化，或同步状态中的对应 hash 被清除后，才会再次进入上传候选。

### F. 通知与触觉反馈

#### 为什么开启通知后仍收不到提醒？

依次检查：

1. CodexBar「系统通知」总开关是否开启。
2. macOS 系统设置是否允许 CodexBar 通知。
3. 通知子面板中的对应类型是否开启。
4. 额度数据是否可信，或任务类型是否需要 Hook。
5. 任务完成耗时是否达到所选阈值。

#### 为什么短任务没有完成通知？

任务完成通知只针对达到所选时长阈值的任务，默认阈值为 1 分钟。

#### 为什么短暂出现「等待批准」却没有通知？

`PermissionRequest` 也可能由 Codex 自动审批产生。CodexBar 会同时检查当前 turn 的审批 reviewer，只有明确路由给用户并且批次结束后仍在等待时才进入等待状态；自动审批或同一批内已经恢复运行、完成的任务不会发送等待提醒。

#### 为什么触觉反馈没有感觉？

触觉需要通知总开关和任务触觉选项开启，也需要 Hook。最终反馈由输入设备、系统设置和辅助功能决定，部分鼠标或触控板不会产生明显反馈。

### G. 快捷键、日志和更新

#### 为什么无法直接覆盖当前快捷键？

为避免录制时误触发当前全局快捷键，需要先点击叉号清除，再录制新组合。可以随时用回转箭头恢复 `⌘⇧W`。

#### 为什么快捷键提示「至少需要两个修饰键」？

全局快捷键必须至少组合 `Control`、`Option`、`Shift`、`Command` 中的两个，以减少和普通输入冲突。

#### 日志窗口关闭后记录会消失吗？

关闭日志窗口不会立即清空当前进程中的记录；点击日志顶部「清空」或退出 CodexBar 才会清除当前内存日志。

#### 为什么设置中显示两个 Codex 版本？

CodexBar 会同时探测全局 CLI 和 Codex.app 内置 CLI，并标记当前 app-server 实际使用的一项。这样可以排查「磁盘已经更新，但当前连接仍来自旧版本」的问题。

#### 自动更新关闭后还能更新吗？

可以。点击设置底部「检查更新」，或在发现更新后点击版本行右侧的更新按钮。

## 11. 隐私与数据边界

CodexBar 的主要账号、额度和 Token 数据通过本机 Codex app-server 获取并在本机处理。

默认本机 Hook 数据位于：

```text
~/Library/Application Support/CodexBar/HookEvents/
```

CodexBar 最多保留最近 210 天的本机 Hook 事件和每日聚合。关闭 Hook 不会自动删除这些文件。当前版本没有单独的历史清除按钮；如需清除本机记录，应先关闭 Hook 和跨设备同步、退出 CodexBar，再通过 Finder 的「前往文件夹」检查并移除上述目录。已经上传到 CloudKit 的聚合不会因为删除本机目录而自动删除，当前版本也没有远端历史删除入口。

CodexBar 不在 UI 中展示完整工作目录、会话 ID 或轮次 ID，也不会读取或展示 rollout 中的提示词、回复、推理和工具内容。

只有以下功能会产生网络请求：

- 查询手动重置机会的过期时间。
- Sparkle 检查和下载更新。
- 用户明确开启跨设备同步后的 CloudKit private database 请求。

更详细的边界见 [README 隐私说明](../README.md#隐私)、[Codex Hook 文档](CodexHook.md) 和 [跨设备同步文档](CrossDeviceSync.md)。
